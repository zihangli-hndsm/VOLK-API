# Compatibility

ML package/runtime facts were confirmed by the owner and independently checked during the R2 acceptance phase. Cloud facts were independently checked against the post-R3 `main` state as of 2026-10-12; private acceptance revisions are recorded in VOLK-Dev.

- **Implemented by VOLK-ML R1:** Episode Package v1 requires explicit supported schema and capability versions. Unknown package or capability versions fail validation; do not guess compatibility.
- **Implemented by VOLK-ML R1:** package content is discovered from static build inputs. Runtime hot installation, arbitrary disk scanning, user upload, and external package resources are not supported.
- **Public stable Episode Package v1 capability (Architect decision 2026-10-12):** `sampling-variability-world`, scenario source version `1`, is the only preset identifier approved for third-party package references. “Source version 1” binds this capability through the Episode Package v1/catalog v1 contract; it is not a separate field or runtime-enforced preset version. The package wire shape remains `{ "kind": "preset", "id": "sampling-variability-world", "seed": <integer> }`; no recipe field or runtime capability is added by this decision.
- The minimum verified application version is `0.1.0` on the accepted R2 implementation. There is no released minimum application semver or runtime version gate; `0.1.0` is the first verified version, not a promise that every later semver will retain support. A compatible successor must preserve this contract. Applications without Episode Package v1 support must reject the package rather than reinterpret it.
- The preset uses `data-lab` with `linear-regression`. It generates a linear World (`y = 1.5x + 0.5`) with additive Gaussian noise amount `0.8`, 12 train and 12 test observations, uniform input in `[-2, 2]`, and zero outliers. It generates its initial World/Data; no external dataset is loaded. The initial model has weight `0`, bias equal to mean training `y`, learning rate `0.05`, 20 training steps, residuals/best-fit display off, and no training fit has yet run. The sample package's seed is `8201`; accepted package seeds are integers `0` through `4294967295` and replace the preset's `seedSource: "entrance"` seed at World regeneration.
- Third-party packages may combine the currently documented public capabilities to author original learning flows. They cannot provide arbitrary initial-scenario recipes. New generators, models, actions, detectors, or presets require a separate runtime capability and acceptance phase.
- An unchanged preset ID/version must not silently acquire a different model, generation process, or initialization meaning. An incompatible change requires an explicit new contract/identifier and migration path; previously authored packages must not be silently reinterpreted. No cross-backend bit-for-bit floating-point guarantee is made.
- Runtime note from the accepted R1 audit: package fingerprints cover package JSON, not the preset implementation, and no automated semantic immutability guard currently ties this preset ID to a configuration fingerprint. Treat this compatibility statement as a release obligation; record an automated guard as follow-up debt if ML does not add one.
- The R2 package validator rejects internal registered presets in both third-party learning and Director `initialScenario` fields. Only the source-scoped first-party Episode manifest receives the internal Director exception; the public sample and other catalog entries do not. Dev independently verified both rejections and retained first-party Director behavior.
- Cloud is optional to local exploration and Episode fallback.
- **Implemented on Cloud `main` as of 2026-10-12:** `GET /health` v0 and legacy `POST /v0/lumi/respond` v0. The route rejects unknown fields and unsupported versions; the R3 delivery also adds bounded request bodies/deadlines and sanitized typed failures.
- **Experimental and not on Cloud `main` as of 2026-10-12:** optional `learningContext` and response `candidateId` correlation.
- An omitted `learningContext` retains the legacy path. A contextual request must not be retried without its candidate constraints. If an older strict server rejects the field, VOLK-ML uses the local fallback.
- **Implemented by VOLK-ML R1:** the client checks current session, package fingerprint, node, and request generation before applying contextual results. Cloud validates fingerprint syntax only and cannot read current client state.

The original Episode example uses the public stable `sampling-variability-world` preset also used as a generic experiment starting point by formal Episode 1. Sharing this runtime capability does not grant access to formal course files, copy, private LUMI assets, or internal registry identifiers. The only approved public preset in this candidate is `sampling-variability-world`; all other registered presets remain unavailable to third-party packages.
